# LouafiPOS — قائمة النقائص والتحسينات للوصول إلى تطبيق مثالي

> آخر تحديث: 12 أغسطس 2026
> الإصدار الحالي: v2

---

## 🔴 أولوية عالية (ضرورية لتشغيل متجر حقيقي)

### 1. المرتجعات والمسترجعات (Returns & Refunds)

- **المشكلة**: لا توجد أي آلية لإرجاع منتج أو استرداد أموال.
- **المطلوب**:
  - [x] جدول `returns` في قاعدة البيانات (يرتبط بـ `sale_id` الأصلي).
  - [x] واجهة `ReturnDialog` تسمح باختيار فاتورة سابقة وإرجاع منتج منها.
  - [x] إعادة المنتج المرتجع إلى المخزون تلقائياً.
  - [x] حساب المبلغ المسترد (نفس سعر البيع الأصلي).
  - [x] منع التلاعب: يجب أن يكون المرتجع مربوطاً برقم الفاتورة الأصلية.
  - [x] زر "مرتجع" في واجهة البيع الرئيسية للوصول السريع.

### 2. إدارة المشتريات وسجل الموردين (Purchases & Supplier Ledger)

- **المشكلة**: الموردون موجودون كجدول فقط، لا توجد فواتير شراء ولا حساب تكلفة تلقائي.
- **المطلوب**:
  - [ ] جدول `purchases` + `purchase_items` (مثل `sales` و `sale_items`).
  - [ ] واجهة `PurchaseView` أو تبويب داخل `SuppliersView` لتسجيل فاتورة شراء.
  - [ ] تحديث المخزون تلقائياً عند تسجيل عملية شراء.
  - [ ] حساب **متوسط سعر التكلفة** (Average Cost) تلقائياً عند كل عملية شراء.
  - [ ] دفتر حسابات الموردين (مثل `DebtEntry` للعملاء): `supplier_debt_entries`.
  - [ ] سجل دفعات للموردين مع متابعة الرصيد.

### 3. إغلاق الوردية والصندوق (Shift / Register Closure)

- **المشكلة**: لا توجد أداة لمطابقة النقد الفعلي مع المسجل في النظام.
- **المطلوب**:
  - [ ] جدول `shift_log` (وقت بدء الوردية، وقت الإغلاق، المستخدم).
  - [ ] واجهة `ShiftClosureDialog` تظهر:
    - إجمالي المبيعات النقدية خلال الوردية.
    - إجمالي مبيعات البطاقات.
    - المبالغ الجزئية والديون.
    - حقل إدخال النقد الفعلي الموجود في الدرج.
    - حساب الفرق (زيادة/عجز).
  - [ ] تقرير إغلاق الوردية قابل للطباعة.
  - [ ] منع التلاعب: لا يمكن تغيير بيانات وردية مغلقة.

## 🟡 أولوية متوسطة (تحسينات جوهرية)

### 4. إشعارات تنبيه المخزون المنخفض (Low Stock Alerts)

- **المشكلة**: نظام المخزون يعرض الحالة في الجدول فقط، لا توجد إشعارات منبثقة.
- **المطلوب**:
  - [ ] عند بدء تشغيل التطبيق: فحص المنتجات تحت `min_level` وعرض تنبيه.
  - [ ] أثناء البيع: إذا وصل منتج إلى الصفر، تنبيه فوري.
  - [ ] أيقونة إشعارات في الشريط العلوي مع عداد للمنتجات المنخفضة.
  - [ ] إمكانية إرسال تنبيهات عبر البريد الإلكتروني أو WhatsApp (لاحقاً).

### 5. دعم الأرقام التسلسلية وتواريخ الصلاحية

- **المشكلة**: لا يمكن تتبع serial numbers (للإلكترونيات) أو تواريخ انتهاء الصلاحية (للأغذية/الأدوية).
- **المطلوب**:
  - [ ] إضافة `serial_number` و `expiry_date` إلى جدول `products` (اختياريان).
  - [ ] في واجهة إضافة/تعديل منتج: حقول للرقم التسلسلي وتاريخ الصلاحية.
  - [ ] تنبيه عند اقتراب تاريخ صلاحية منتج معروض للبيع.
  - [ ] تقرير "منتجات قاربت على انتهاء الصلاحية".
  - [ ] بحث بالرقم التسلسلي.
  - [ ] في `sale_items`: تخزين `serial_number` لكل قطعة مباعة للرجوع إليها في المرتجعات.

### 6. تفعيل نظام نقاط الولاء فعلياً

- **المشكلة**: `loyalty_points` و `loyalty_rate` معرفان لكن لا يُستخدمان في واجهة البيع.
- **المطلوب**:
  - [ ] إضافة نقاط ولاء تلقائية مع كل عملية بيع (حسب `loyalty_rate`).
  - [ ] عرض نقاط العميل الحالية في خانة العميل أثناء البيع.
  - [ ] إمكانية استبدال النقاط بخصم: "استخدم 100 نقطة = خصم X دينار".
  - [ ] سجل حركة النقاط `loyalty_log` (مكتسبة/مستخدمة/منتهية).

### 7. منع تعديل السعر أثناء البيع حسب الصلاحية

- **المشكلة**: أي مستخدم يمكنه تعديل سعر المنتج أثناء البيع (لا يوجد قيد).
- **المطلوب**:
  - [ ] الكاشير (`cashier`) لا يمكنه تغيير السعر في واجهة البيع.
  - [ ] المشرف (`supervisor`) يمكنه تغيير السعر مع تسجيل السبب في audit log.
  - [ ] المدير (`admin`) صلاحية كاملة.

### 8. وحدات قياس متعددة للمنتجات

- **المشكلة**: كل المنتجات تباع بالقطعة فقط.
- **المطلوب**:
  - [ ] إضافة `unit` (piece, carton, kg, liter...) إلى جدول المنتجات.
  - [ ] دعم التحويل بين الوحدات: مثلاً كرتون = 12 قطعة.
  - [ ] عمود الوحدة في جدول السلة يعرض الوحدة المختارة.
  - ملف `ar.json` يحتوي مسبقاً `piece` و `carton` — تحتاج ربطها.

## 🟢 أولوية منخفضة (تحسينات إضافية)

### 9. دعم العمل بدون إنترنت (Offline Mode)

- **المشكلة**: التطبيق محلي بالكامل (SQLite) وهذا جيد، لكن لا توجد بنية للمزامنة مع سيرفر سحابي.
- **المطلوب** (للمستقبل):
  - [ ] دعم قاعدة بيانات PostgreSQL/MySQL كخيار سحابي.
  - [ ] وضع Offline: يحفظ في SQLite محلي ثم يزامن تلقائياً عند عودة الاتصال.
  - [ ] مؤشر حالة الاتصال في الشريط العلوي.

### 10. الإيصالات الإلكترونية والطباعة المتقدمة

- **المشكلة**: الإيصالات تُكتب كملفات نصية فقط.
- **المطلوب**:
  - [ ] دعم الطباعة على طابعة حرارية (ESC/POS) مباشرة.
  - [ ] إرسال الإيصال عبر SMS أو WhatsApp للعميل.
  - [ ] تصميم إيصال بصيغة PDF.
  - [ ] طباعة باركود على الإيصال.

### 11. لوحة تحكم (Dashboard) مع رسوم بيانية

- **المشكلة**: لا توجد شاشة رئيسية تلخص حالة المتجر.
- **المطلوب**:
  - [ ] `DashboardView` كشاشة افتراضية بعد تسجيل الدخول.
  - [ ] مخطط مبيعات اليوم (خط زمني).
  - [ ] أكثر 5 منتجات مبيعاً.
  - [ ] ملخص: مبيعات اليوم، عدد الفواتير، المصاريف، الأرباح.
  - [ ] تنبيهات المخزون المنخفض.

### 12. نسخ احتياطي تلقائي وتصدير/استيراد

- **المشكلة**: النسخ الاحتياطي يعمل كل دقيقتين لكن لا توجد خيارات استيراد أو تصدير مرنة.
- **المطلوب**:
  - [ ] تصدير البيانات إلى CSV/Excel.
  - [ ] استيراد منتجات من ملف CSV.
  - [ ] نسخ احتياطي يدوي بنقرة واحدة.
  - [ ] الاحتفاظ بآخر N نسخة فقط (تنظيف تلقائي للنسخ القديمة).

### 13. صلاحيات أكثر تفصيلاً

- **المشكلة**: 3 أدوار فقط (`admin`, `supervisor`, `cashier`)، والتحكم في الصلاحيات محدود.
- **المطلوب**:
  - [ ] نظام صلاحيات دقيق (Permissions): لكل دور قائمة صلاحيات قابلة للتخصيص.
  - [ ] أمثلة: "حذف فاتورة"، "تعديل المخزون"، "مشاهدة التقارير"، "إدارة المستخدمين".
  - [ ] سجل `permissions` table + واجهة لإدارة الصلاحيات.

### 14. تحسينات عامة على الواجهة

- **المطلوب**:
  - [ ] دعم الوضع الليلي (Dark Mode) كامل — موجود في `config.ini` لكن غير مفعّل في كل الواجهات.
  - [ ] إمكانية تغيير عدد أعمدة المنتجات في الشبكة (حالياً 3 أعمدة ثابتة).
  - [ ] خيار عرض المنتجات كقائمة بدل البطاقات.
  - [ ] تخصيص ألوان الثيم من واجهة الإعدادات.
  - [ ] اختصارات لوحة مفاتيح قابلة للتخصيص.

### 15. أمان إضافي

- **المطلوب**:
  - [ ] قفل تلقائي للتطبيق بعد فترة خمول (`inactivity_timeout` موجود في config لكن غير مفعّل).
  - [ ] تحديد عدد المحاولات الخاطئة لتسجيل الدخول مع قفل مؤقت.
  - [ ] تسجيل محاولات الدخول الفاشلة في audit log.
  - [ ] تشفير قاعدة البيانات (SQLCipher).

### 16. دعم متعدد الفروع والمستخدمين المتزامنين

- **المشكلة**: تطبيق سطح مكتب لمستخدم واحد.
- **المطلوب** (للمستقبل):
  - [ ] دعم فتح التطبيق على أكثر من جهاز مع مزامنة البيانات.
  - [ ] تحديد فرع لكل مستخدم/جهاز.
  - [ ] تقارير مجمعة لكل الفروع.
